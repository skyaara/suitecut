Context handler and HAR removal
==============================

`NativeContextUnrouteAll` coordinates two actual native policy managers on the
UI actor. Each manager first allocates its full candidate queues and batch map
node. The coordinator also reserves its combined observer and bounded generic
callback identity receipt before deactivating either family's registrations.
Both reservations are validated before two callback-free, allocation-free
commits. Only then does it publish admission and begin physical target removal.
An allocation, capacity, context or deadline failure during preparation leaves
both original policy sets intact.

Target removal follows any earlier dispatched bootstrap installer ACK. Native
removal callbacks and their immutable policies survive cancellation. Cancellation
removes the logical observer, never the physical sender receipt; cancellation
inside the synchronous admission receipt still dispatches committed removals.
New targets inherit the policy sets after the transaction. Page-owned routes
belong to neither context manager and are excluded.

`NativeHARWorkLeases` represents native HAR replay Fetch work and independent
request-body reads. A receipt can settle only through its actual native ACK or
an explicitly supplied real channel-close boundary. A logical timeout, dropped
observer, erased pause, Data callback or renderer navigation is insufficient.
Lost observation remains unavailable and physically charged. Snapshots match
the exact immutable policy, including its admitted native manager/context claim;
another registration using the same archive is a different policy. Each native
Seed has an independent policy-owner pin; closing and recreating the same
numeric context cannot capture prior retained callbacks/work or revive an old
empty prepared transaction.

The combined wait observer requires real policy-removal ACKs from both families.
`wait` additionally observes the exact captured generic callback and HAR work
receipts. Default and `ignoreErrors` do not await earlier admitted work, whose
physical owners continue independently. `ignoreErrors` remains a policy for
genuine language callbacks, never native read or Fetch failures. The observer
uses the original absolute operation deadline, including an ACK arriving before
the next timer tick. It cannot create language callback IDs for native HAR work.

Engine wires this coordinator through `context_route_engine.inc`, context
close/cancellation and its native tick/physical-work fences. `NetworkControls`
produces the independent HAR read/Fetch receipts and removes bindings by exact
policy identity. The SDK observes native generic-callback mutation identities
for `wait` and `ignoreErrors`; native HAR work does not acquire invented
language callback identities.

Controlled CEF-valued tests exercise those manager and producer methods.
Component optimized/sanitizer results do not establish browser acceptance.
A matching compiled browser/SDK epoch and the unchanged
`library/browsercontext-har.spec.ts:569` oracle remain the public acceptance
gate; this source wiring correction adds no new runtime acceptance claim.
