# Captured frame debugger binding

This slice binds `NativeFrame.createDebuggerSession()` to a genuinely observed
current default document. The native controller and adapter controls pass;
compiled browser proof is still pending. Compose the central Source patch after
the eager document ledger/root-adoption Kit A. Validate the existing root
inventory and paused-evaluation checks before the new frame browser checker.

Each controller captures the Source namespace, observer stamp, actual CDP
session, accepted attachment incarnation, frame, loader, native document serial,
default context ID and Runtime unique context identity. The core receives the
actual captured session for arbiter acquisition; the sender retains its original
attachment check even during late cleanup. The document serial is separate from
the Source renderer epoch used to identify actual root V8 realm destruction.

A same-process child and the root share one Inspector channel and one physical
scope fence. A root/child/sibling controller cannot open that channel while a
previous controller retains a lease, accepted callback, breakpoint removal or
result-group cleanup. An independent OOPIF uses its actual accepted session and
may coexist with a root controller. Worker and context-broker channels are not
included. Frame admission requires current default metadata; it does not invent
a context or renew a startup deadline while a frame is loading. Existing root
open-before-default retains its original bounded native metadata waiter.

Frame sessions expose actual observed author pauses, resume, script metadata and
source, exact-script breakpoints, and primitive by-value paused-frame evaluation.
Agent-wide `pause` and step commands are explicitly unsupported for frame
sessions. Both native and SDK guards reject them before sending a command or
consuming a current pause. Root page sessions keep those existing commands.

The per-session arbiter routes native factory breakpoints first. Scoped author
pause classification uses actual script/context inventory. A foreign top frame
is resumed by the arbiter without publishing its IDs or invalidating our
controller. Unknown metadata, attested native frames, and mixed ancestor stacks
remain unsupported. URLs, source hashes and matching builtin tuples confer no
mutation authority. No pause continuation belongs to two consumers.

Document invalidation begins logical cleanup on the exact captured record;
callbacks retain both arbiter and scope receipts until actual replies/refusal or
proven channel closure. Actual initial-root renderer death invalidates its
same-process child realms; independent OOPIF records are excluded. Context or
frame registry erasure alone cannot close an Inspector channel. The Source
session teardown calls frame channel closure only after its existing actual
callback/arbiter drain. Cleanup watchdogs request posted Source teardown and do
not retire physical work themselves.

A Source admits at most eight live frame controllers and retains at most 32
captured records including completed-close metadata. Record eviction removes
only physically retired metadata. It never retires an accepted callback. A
completed-close token is retained only after the actual controller ownership
retires; the first terminal close error, including its original deadline error,
stays an error. Cancellation of a logical observer without a terminal failure
can join the exact eventual physical retirement. Unknown or evicted tokens fail
explicitly. SDK canonical cleanup forwards the old frame ID and native token
under the genuine page/Source lifetime, independently of constructor cancellation
or a frame facade's local detached flag.

Controlled validation covers 46 controller cases, eight captured-target cases and
six included production Source adapter cases in optimized and ASan/UBSan/LSan
builds. The SDK projection has 34 focused tests. Those controls use explicit
sender/metadata seams; they are not actual browser acknowledgements. The future
browser check must run against one matching immutable SDK/native build with
strict native diagnostics, actual helper closure and complete input audits.
