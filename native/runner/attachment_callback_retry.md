# Attachment callback-iteration attribution

`AttachmentRetryProvenance` is private native attribution, separate from the public attachment's `step_id`. Its `assertion_id`, `invocation_nonce`, and `iteration_step` must all be present or all absent. The native callback retry controller authenticates the complete original `StepOwner`, real current assertion/invocation/iteration identity, public owner ancestry, and whether an operation is new admission or an already admitted continuation.

`TestInfo.attach` keeps public `step_id=0`. An attachment through captured explicit `StepInfo` retains that explicit step ID. The actual job, immutable declaration, successful artifact, and genuine publication receipt retain separate private iteration provenance. Existing record/metadata/process budgets remain authoritative; no parallel history is created.

`PendingRetry` and `FenceRetry` join actual writer/rollback waitpid and publication receipts to the genuine iteration step. The original public step and private iteration both retain their actual file/publication fences and deadlines: a nested explicit public step cannot retire before its own file/view receipt, and its stricter native cap still cancels the file job. Closing author admission cannot retire those physical owners. Ordinary input/read/write/fsync/publish failures reach the native retry controller only after a genuine normal writer exit and successful rollback reconciliation. Failed immutable declarations remain in the report journal and no longer independently re-poison the outer callback after their owning iteration has handled them. A failure after raw callback success still fails the owning iteration. Ordinary iteration-owned errors reach the exact iteration and the original public step’s ancestor path inside that iteration. Unrelated descendant steps and captured outer/sibling public steps retain physical ownership without inheriting the iteration’s ordinary error. A nested public step therefore retains genuine failed attachment history while a captured outer step is not poisoned. Hard infrastructure failures retain their independent native veto.

Writer failure origin is typed at native throw sites. An opt-in `R` field on the actual writer's `INIT` requests a final `O` (operation) or `I` (infrastructure) field on its `ERROR`; default writer bytes are unchanged. Unexpected death, bad control/protocol/identity, native invariant failure, actual mutation failure, and failed rollback remain hard failures. No error text/class or successful JavaScript promise is a physical receipt.

Author `ATTACH_BEGIN`, `ATTACH_STEP_BEGIN`, `ATTACH_APPEND_BEGIN`, and `ATTACH_MUTATE` optionally append the three private IDs. Genuine job `CHUNK`/`FINISH` continues using its original admitted native identity. Existing failed `RESULT`/`ADMITTED`/`APPEND_REJECTED` packets append `O` or `I` only for an admitted retry scope; mutation rejection appends `I`. Success and all default packets keep their previous shape. The SDK retains private provenance of the original admitted operation for a publication ACK after raw callback settlement; new author operations must use a live scope.

Publication receipts keep their original public deadline/cleanup authority. The assertion scheduler separately owns its original assertion deadline and cleanup cap: late genuine ACK cannot make an expired assertion pass or reopen author admission.

`attachment_callback_retry_test.cc` verifies real writer/rollback/file/waitpid behavior, public owner preservation, private fences, reference-only declaration, ordinary missing-source recovery, unawaited actual EFBIG after raw success, unexpected actual writer SIGKILL, bounded admission rejection, hard mutation rejection, and stale author admission. Its controller validation callback deliberately uses controlled native identities around genuine `TestSteps`; it does not claim integrated retry-controller/Source/API verification.

`attachment_callback_report.h` validates optional private report metadata against the exact native iteration and first assertion identity, owner, ancestry, admission time, and physical endpoint. Historical admission bounds use immutable step `own_deadline` and fixed callback assertion caps; a live owner amendment may shorten the final effective `deadline` to before earlier valid history and does not invalidate that history. Native live admission validation is unchanged. A settled iteration bounds terminal IO by its physical receipt; a genuine worker-exit receipt can precede separately owned rollback retirement. Declaration and actual publication receipt JSON add `callbackAssertion: {id, invocation, stepId}` only when private provenance exists. The separate report controls use explicitly controlled DTOs and make no process/IO provenance claim.

A failed append declaration sets its fixed terminal `retry_failure_disposed` ownership marker only after a genuine ordinary writer/rollback reconciliation (or no-job ordinary capacity rejection) has reached the exact native retry controller. Later test-skip admission ignores only that consumed ordinary row; it keeps the original failed receipt/error/time/provenance, and hard producer/global/mutation failures retain their independent veto.
