# Native soft assertion journal

The following bounded slice composes the existing native runner with async native matchers. Native admission/phase/report controls and actual Node protocol ownership have executed privately. Genuine browser mismatch continuation awaits the separately compiled native cached-observation publication repair; the two preserved browser negatives are described below.

Queries owns source-issued matcher failure receipts: an invocation ticket and exact original Error object identify a genuine mismatch; class names, text, arbitrary author errors and old receipts do not. The runner owns callback context, native admission, original deadlines, actual step ancestry, errors, acknowledgment and final classification. A matcher executes only after SOFT_BEGIN is acknowledged. Success, recognized mismatch, and other actual thrown values have separate settlement receipts. A rejected/late native acknowledgment is hard, never converted to soft success. Existing native matcher execution receives the real cancellation signal and the C++ supplied remaining budget, without a JavaScript timer or Promise race.

The first scope is actual body, beforeEach and afterEach callbacks. BeforeEach soft failure leaves its genuine raw callback result successful and BODY runs. The associated attempt fails only after actual phases and raw/step/file/output fences complete. AfterEach soft failure is cleanup failure and cannot be excused by expectedFailure. BeforeAll, afterAll, fixtures, pure-value soft matchers, APIResponse body diagnostics and undocumented external runner isSoft adapters remain explicit gaps until separately implemented/proved.

Native admission captures the actual callback owner (test, attempt generation, callback token, scope/generation, worker/PID), the optional actual running step and original callback/step/global caps. Later callback settlement closes new admission but does not invalidate an existing request. Logical timeout/cancel aborts the real operation; only actual matcher settlement or confirmed same-host waitpid retires its raw operation lease. Stale/foreign/forged/duplicate requests, receipt IDs and step ancestry reject. Native callback info and worker reuse readiness require genuine soft-context retirement in addition to the existing step/attachment receipts. Terminal soft error history is not live physical work.

The native journal bounds 64 inflight requests globally, 32 retained recognized mismatches per attempt, 8192 diagnostic records globally and 16 MiB of retained metadata. Inflight error storage is separately reserved before execution and remains bounded. Capacity failure is a genuine hard native error, with no dropped error or synthetic pass. Unknown-error allocation failure retains the original raw receipt until actual emergency retirement; publication is refused if its ledger cannot be confirmed.

A source-issued mismatch is recorded separately with its original error/stack and actual captured author location, native owner/request/step identity, admission/receipt timestamps and outcome. A successful matcher creates no error row. Hard authored errors and their existing originating-step receipts remain primary; soft errors are retained separately even when a later hard error occurs. Timeout, interrupt, real cleanup/rollback and infrastructure failure keep their existing priority. Body/beforeEach recognized soft failure is an ordinary failure for expectedFailure; afterEach is cleanup failure.

A softly failed step and its genuine ancestors report failed after their actual raw and operation receipts. Their callback return values still resolve through an explicit native soft-result packet, allowing later statements/steps to run. No ordinary raw failure is swallowed. Step error attribution follows native validated step/box provenance; it is not inferred from equal errors or the last failed step. Primitive/raw-hard attribution gaps remain unchanged.

The public async-only errors snapshot contains original Error objects after their actual native accepted mismatch acknowledgment, shared by exact native attempt identity across supported hooks/body. It is not a host outcome counter. Synchronous pure-value expect.soft followed immediately by errors.length is not claimed. Pending soft requests/local-step cancellation and accepted test skip require explicit native preflight; unsupported combinations reject rather than invent cancellation receipts.

Meaningful controls must include raw-PASS attempt failure, beforeEach continuation, afterEach cleanup priority, nested soft step continuation, hard/raw error priority, ignored async mismatch, actual cancellation/late receipt/worker exit, retries/parallel owner isolation, invalid private matcher receipt and native capacity negatives.
