# Native attachment declarations and committed snapshots

This is the following slice's contract, not a passing implementation claim.

`NativeTestInfo.attachments` and `NativeHookInfo.attachments` expose a bounded append/read view with the familiar `name`, `contentType`, optional `body`, and optional `path` fields. `push(...items)` validates the complete batch synchronously, snapshots body bytes before sending any request, appends actual author declarations, and returns the new declared length. The view supports ordinary indexed reads, length, iteration, and non-mutating Array methods. Non-append mutations (`pop`, `splice`, index assignment, length assignment, deletion) reject explicitly before native requests. Mutable-array parity beyond append/read is not claimed.

Declared, committed, failed, and accepted-cancellation states remain in the private host/native ledger. Public items acquire no mandatory implementation-state fields. An author's supplied path is merely that actual declaration, never a fabricated committed artifact reference. Ordinary `attach()` publishes an item after its actual success, while synchronous `push()` exposes the declaration immediately. An ordinary path-copy attach exposes its actual copied path only after successful native publication; a pushed path reference remains exactly the authored path. Public body values reflect actual snapshotted author bytes; modifying an exposed byte array cannot change an admitted writer payload.

Before any real BODY/CALL invocation, native `ATTACH_CONTEXT` pins the exact callback token/scope/generation to its actual test/attempt generation, worker index and host PID. Host views are keyed by that native attempt identity, not guessed hook scope or test title. Same-attempt beforeEach/body/afterEach callbacks share one view. Retries, different tests, workers and projects cannot share it. BeforeAll/afterAll use their actual native-associated test/attempt identity; no invented suite-wide attachment ownership is introduced.

Path append is an authored reference, not an `attach({path})` copy request. A bounded native declaration record preserves the exact author path without claiming existence, byte length, writer PID, file ownership or a commit receipt. An item with no body/path remains source-absent metadata; an explicitly zero-length body is distinct and can materialize a real zero-byte native file. Body append reuses the existing native attachment controller, request nonce, actual byte writer, original callback deadline and immutable operation cap. `push()` performs no file I/O and does not schedule native work. The existing native physical limit4, catalog128, total byte64MiB and per-file16MiB bounds remain enforced; an excess concurrent admission rejects honestly. The host bounds authored append declarations to 128, native published artifact views to the existing native 128-file capacity, and pending native rejection tracking to 128 additional requests (384 private entries total); pending and retained body bytes are bounded. A full committed view must not preempt the existing asynchronous native over-capacity rejection. No JavaScript queue bypasses native capacity.

Every author declaration has a native callback-owned outcome ledger entry before its request can create a file process. Native admission rejection or actual writer/copy failure is retained on that exact callback even when no returned Promise exists. A failed declaration does not manufacture a committed artifact. Accepted native test/local skip cancellation is a separate typed cause; it is not detected by matching error text. Real cancellation error, rollback error, deadline and infrastructure priorities remain unchanged.

Native declaration acceptance and native artifact publication are distinct typed receipts. Reference acceptance acknowledges only the authentic metadata declaration. A successful body-file publication receipt is emitted only after actual COMMITTED, final IPC drain, exact writer waitpid exit0, actual byte/device/inode validation and ordinary deadline checks. It carries the exact actual owner, request/artifact ID, name, contentType, source kind, copied path, bytes and real step provenance. The host verifies it against the pending request and native attempt context before updating its view. Success ACK without that publication is invalid. Failed or canceled requests cannot publish a successful receipt.

Callback settlement waits the original raw callback/step receipts and all genuine attachment writer/rollback receipts. Native append failure turns an otherwise successful callback into an actual failure before fixture teardown/afterEach admission. If the author callback already failed, its original error and originating-step source stay primary; the append failure remains a distinct native report record rather than replacing the raw error by string comparison. Existing expected-failure classification still applies to ordinary action failures; real rollback/cleanup/infrastructure failure retains its existing override. Reports keep all distinct actual declaration failures with their native owner/request identity, separate from committed artifact rows.

The host may observe the Promise associated with its own synchronous append request solely to avoid an unhandled rejection; it cannot erase a native failure, settle callback ownership, declare a path committed, or manufacture a cancellation receipt. Native fences, not host Promise completion, control phase continuation and report publication.

Planned controls cover source-absent versus zero-byte body, missing-path references without fabricated file claims, body+hook append, same-attempt view identity, body bytes and path copy, UTF16 names, original budget expiration, admission capacity, ignored failing append, raw boxed error plus separate append failure, static/dynamic expected-failure behavior, typed accepted skip cancellation, actual held writer and rollback fences, retry isolation, stale/foreign publication rejection, invalid complete-batch validation without requests, and unsupported mutation rejection. No unchanged upstream direct-push or full mutable-array claim is made until its actual complete required behavior executes.
