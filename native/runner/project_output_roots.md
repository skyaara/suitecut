Native declared-project output roots
===================================

`NativeProjectDefinition.outputDir` overrides the launch `outputDirectory`
fallback for that actual project. Relative declarations resolve against the
canonical suite module's parent, including each genuine file of a directory
run. Native C++ validates scalar filesystem UTF8, the 7900-byte path bound,
actual local project membership, immutable retry catalog, and the 128-project /
2 MiB per-catalog declaration bounds. The SDK emits metadata and receives native context.

An explicitly configured root is exposed as `info.project.outputDir`; existing
unconfigured project objects keep their original shape. `info.outputDir` and
`outputPath()` refer to the unique native-assigned attempt child, whose real
writer exit, inode validation and host ACK precede callbacks. Shared native
output IDs and physical/metadata budgets preserve retry, parallel and cross-file
isolation even when different projects choose the same root.

Listing projects includes configured resolved roots and performs no directory
IO. Permission, existing-file and inode failures remain actual native IO errors.
The feature does not sweep user roots: preservation policies operate only on
actual assigned child directories after existing global physical fences. Real
committed attachment references retain their independent original receipts.
Snapshot paths and templates are separate.
