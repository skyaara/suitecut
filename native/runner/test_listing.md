# Native declaration listing

`suitecut-test --executable /absolute/suitecut-runner --suite /absolute/suite.mjs --report /absolute/list.json --list` imports and validates the real suite declarations in one owned module host. Importing executes the module's top-level code. Native C++ does not admit fixture setup/teardown, hooks or test bodies. The host and its actual descendant batch retire before the listing is atomically published.

The same `--test-id`, `--project`, `--no-deps`, `--forbid-only` and `--shard` native selectors apply to listing and execution. IDs remain the original declaration IDs. Required project dependencies and teardown retain the execution selection contract: support projects are listed whole; only primary tests consume the shard. `--workers` is accepted, but listing uses one collection host. `--global-timeout` includes real loading and cleanup. `--junit`, `--html`, `--output-directory` and `--max-failures` are rejected with `--list` because they describe execution output or admission limits. The public `runNativeSuite` adapter accepts `list: true`; JavaScript transports options and declarations, and does not compute selection.

The JSON has `version:1` and `kind:"suitecut-native-test-list"`. It is separate from native execution reports and cannot be merged as an execution report. `tests` includes selected and excluded declarations with original test/project/suite IDs, literal UTF16-safe JSON titles, resolved fixture roots, timeout/retry/expected-failure settings and resolved inherited skip/focus metadata. `suites` retains the hierarchy and positions. `projects` retains every declared project, complete opaque metadata (including unknown keys), dependencies/teardown/default settings, selection role and original selected test IDs. `collectionProtocolUTF8Hex` retains the exact bounded metadata transcript, including hook, fixture, lock and parallel declarations. The `effectiveFixtures` field contains requested roots after fixture version/name resolution; automatic/transitive fixture declarations remain in the transcript. This is metadata evidence, not evidence of executing those declarations.

`collectionWorkers` records the actual module-import PID/index, OS exit and captured stream bytes. These are collection processes. There are no attempts, execution worker records, test outcomes or invented lifecycle receipts. File device/inode facts come from an actual retained read-only suite descriptor; they do not claim imported dependency identity or atomicity between opening and JS import.

Success returns 0. A genuine collection or selection failure returns 1, retains available declarations with `selected:null`, sets `selectionResolved:false` and records errors. Argument, publication, source-identity-change or unconfirmed physical cleanup errors return 2. An interrupt returns its signal status after actual retirement. Publication rejects lexical/canonical/inode aliases of the suite, host script or node executable. No output is written before collection retirement.

The public control script creates a fresh retained run directory on each invocation. It compares actual list and execution IDs, proves callback sentinels remain untouched during listing, checks actual import failure and worker exit, and protects original input bytes through real hardlink alias controls. No browser process, upstream runner code or mocked process cleanup is used.
