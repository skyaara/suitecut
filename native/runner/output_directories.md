# Native attempt output directory contract

The default root is `parent(report)/test-results`. `NativeSuiteRunOptions.outputDirectory` and `suitecut-test --output-directory /absolute/root` select one global parent for the native per-attempt directories. Native C++ validates and lexically normalizes a bounded absolute filesystem UTF8 path before loading any host. The SDK rejects invalid UTF16/NUL/byte bounds before spawning the native executable. Neither syntax check performs IO or promises the parent is writable; the native actor creates it and reports genuine filesystem failures. Project-specific root configuration remains separate.

This slice adds `NativeTestInfo.outputDir` and `outputPath(...relativeSegments)` to genuine body and hook callback admissions. The first directory for an actual attempt is created before any of its callbacks or fixture acquisition. All hooks associated with that attempt use its directory. Every retry, serial-group replay, and project attempt receives a distinct root. Declarations omitted by selection, static skip, runtime subtree skip, or a scheduling stop receive no invented directory or attempt.

Both active and final record nodes are allocated and the shared physical capacity is reserved before the real fork. A post-spawn initialization/Send allocation failure remains an owned physical job until actual child exit; final-record admission uses a noexcept move into its reserved node.

The directory is an owned native IO operation. A dedicated C++ helper creates the parent and child, opens the actual parent/child with `O_NOFOLLOW`, records device/inode values, fsyncs both, and rechecks path identity before reporting readiness. The runner requires the real writer process exit and drains its final control packets before advertising readiness. It then sends `OUTPUT_CONTEXT` containing the exact native attempt generation, worker index, PID, directory identity and path. The actual host must ACK that identity before native callback admission. A successful directory record alone is not a callback admission receipt.

`outputPath` performs a bounded lexical join in the host. It creates no directory, file or attachment. Absolute segments, NUL, traversal outside the assigned root, and excessive counts/bytes are rejected. Returning a child path does not imply that a child exists. User callbacks may create their own files there; those are user files and are not automatically counted as committed native attachments. `attach({path: info.outputPath(...)})` remains the actual native read/copy operation with its existing writer receipt.

Directory preparation consumes the original test budget. Flat tests keep their original attempt start. Hooked tests carry the measured native preparation duration into the beforeEach/body group; beforeAll retains its independent phase budget. The test timeout's amendment origin includes that consumed preparation, while afterEach has its normal separate cleanup budget. Observed duration counts preparation once. A global deadline still caps every phase, and a native directory operation has a maximum120s admission deadline.

Cancellation retains the writer until its actual exit, then invokes a separate native rollback helper for a directory whose actual inode was received. Rollback deletes only the empty directory matching both the recorded parent and child identities. Foreign replacements are preserved. Failure to remove or fsync is a real cleanup failure. Before the actual inode receipt, an interrupted helper may leave an unclaimed empty directory; the runner never deletes by an unverified path. No user callback was admitted in that state. Successful assigned output directories and user-created children are retained.

Output helpers borrow the same run-wide physical counter/capacity as attachment IO helpers. Each actor owns its writer/rollback waitpid receipts. Project completion, serial retry, shared subreaper-domain arrival, worker capture and report publication all require output physical retirement alongside raw callbacks, attachments and descendant cleanup. A generic `waitpid(-1)` domain cleanup cannot consume an output helper's exit.

Reports retain genuine directory owner IDs, writer and rollback exits, monotonic receipt times, errors and identity metadata. An assigned `outputDir` appears only after the actual host ACK; a failed/unassigned proposal is labeled `proposedPath`. JSON is lossless for supported filesystem UTF8; XML/HTML apply the existing visible sanitation rules. No arbitrary user-child files or file receipts are synthesized.

Fixture-level outputPath, mutable `TestInfo.attachments` declarations, project output-directory configuration and boxed step attribution remain separate contracts. This document states the intended slice; actual public/process validation is recorded separately from controlled component checks.
