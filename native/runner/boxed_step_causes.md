# Native originating-step failure receipts

This slice links attempt errors to actual step failures without comparing text or modifying any thrown value or stack. Primitive values have no reliable causal identity and remain unattributed. Native-generated timeout/file Error wrappers are initially outside this identity bridge; their existing status, error and physical receipts remain intact.

The host keeps a weak object-keyed ledger, partitioned by exact callback owner and actual native step ID. It never overwrites one shared Error object's sibling origins. Each entry refers to bounded native-admitted async ancestry. For a parent step, only same-owner recorded descendant failures are eligible; for the outer callback, only its same-owner entries are eligible. A genuine already-propagated ancestor receipt supersedes its descendants, while incomparable sibling origins remain ambiguous and produce no originating-step claim. Catch then rethrow of the same original object is supported. Catch then success, a new Error with equal text, foreign callback reuse, and unrelated sibling reuse cannot fabricate a causal edge.

A typed step raw-failure receipt may name an actual descendant source. C++ validates the real callback/attempt/worker/PID, native parent chain, admitted source and raw failure state before recording the edge. Source metadata never turns callback invocation into physical settlement. Typed outer BODY/CALL failure receipts identify the genuine source chosen by the identity ledger, and C++ validates that same native callback ownership before associating it with the actual phase error. Fixture, deadline, cancellation and file-fence failures carry no invented originating-step ID. Hook phase error metadata must remain aligned with the actual error occurrence so cleanup cannot acquire another callback's source.

Native attempts retain a bounded originating-step ID receipt. Report writers follow only native-pinned causal edges and prefer the outermost boxed step on that actual propagation chain; an unboxed wrapper can preserve a boxed child source. No general parent walk infers propagation merely because an ancestor failed. The chosen attribution is primary for the relevant failed attempt in JSON/JUnit/HTML, while raw error text and original per-step source metadata remain available. Timed out/interrupted attempts keep their existing outcome priority and do not present an earlier boxed error as the primary timeout/interruption location.

Existing native metadata limits remain unchanged; each source ID is charged in the reservation before author code and in the final report budget. Original attempt/callback/step deadlines, global identities, raw callbacks, file/output rollback, project/work-group and descendant waitpid fences remain unchanged. Every claimed source must reject forged, foreign or stale IDs. Admission closure on cancellation does not erase the raw callback lease: a genuine late source receipt may still retire that exact physical callback, without resurrecting admission or providing primary timeout/interruption attribution. Duplicate source claims after outer-result forwarding remain stale. Concurrent shared-object controls cover distinct sibling origins and explicit ambiguity rather than fabricated causality. A separate typed native source receipt accompanies the raw outer error through the step/file callback fence; an optional error value alone is never used to distinguish raw author failure from cleanup failure. The native fence still waits the actual raw callback receipt before forwarding source metadata.

This contract describes SuiteCut’s JSON/JUnit/HTML attribution metadata. It does not rewrite an Error object, its stack, primitive throws, or external reporter stacks. Primitive throws and incomparable reuse of the same object intentionally omit a causal claim. Caught failures that do not fail the outer callback retain only their genuine per-step records. Native-generated timeout/file wrapper identity is not inferred. Actual source receipt and timeout/interruption priority are separate, so a late owned raw failure may remain recorded without becoming the primary timeout location.

JUnit’s failure display prefixes the selected genuine boxed location before the original error text; the native.attemptN.error property remains the exact raw error (subject only to declared XML1.0 sanitization). Per-location sanitization counts identify invalid XML units, while canonical JSON retains those original UTF16 units. This is native reporter presentation, not a rewrite of author stack objects.
