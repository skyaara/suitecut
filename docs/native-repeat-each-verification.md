# Native repeatEach process verification

The public process checker is `scripts/check-native-runner-repeat-each.py`. It requires a matching native repeat activation and emitted SDK. The current pre-feature runner must never be used to claim this feature works. `--prepare-only` invokes only Node `--check`; it neither imports generated modules nor launches the native runner.

The contract comes from the pinned public stock observations at `/tmp/suitecut-repeat-contract-v1/report.json` and `/tmp/suitecut-repeat-contract-matrix-v1/contract-summary.json`, together with the approved native integer domain. Raw zero remains zero in configuration but executes once at index zero. CLI overrides affect primary projects; dependency and teardown projects use their own resolved declaration. Repeats expand before shard selection, retaining native indivisible group widths.

The checker owns fourteen bounded actual invocations:

| Case | Genuine observation |
| --- | --- |
| Omitted, explicit one, explicit zero (three) | Original direct report, one import in the actual callback worker, one body, local ID unchanged, index zero. Omitted configuration additionally appends a benign comment to its own module during first import; actual body `/proc/<native PID>/fd` observation requires the provisional suite descriptor already closed, without imposing new immutable-version rejection. |
| Root zero with named project one | Raw root zero and project-one declaration remain typed configuration metadata; no promotion, one import/body and legacy public ID. |
| Directory selects setup with CLI zero | With setup declared once and an unselected dependent body, the outer selection keeps setup primary. Raw CLI zero resolves to effective zero and one actual callback; child-local default graph selection must not relabel it dependency. No repeat selection or extra source is invented. |
| Repeated test with one retry | Repeat zero fails then retries in a fresh worker; repeat one starts with retry zero and a different native public ID. Public ID is stable through retry. All real worker fixture setups and after-use teardowns complete. Actual output paths differ, snapshot baseline path is unchanged, failed output is kept and successful output removed after physical retirement. |
| Primary CLI override and support | Root count three becomes primary count two; declared one for setup/teardown remains one, with dependency/cleanup order. |
| Default and fully parallel shards (four) | Two declarations repeated three times yield actual grouped shard membership 4/2 or fully parallel 3/3, as native policy selects, without constraining parallel callback completion order. |
| Shared workers | Two real files repeated twice rendezvous through genuine body beacons. Native host timing proves at most two observed live hosts and actual overlap; final native receipts separately prove all physical credits retired. It does not infer full reservation duration from waitpid timing. |
| Original global deadline | First repeat waits for its genuine native abort; later repeats are native selection-only rows without fake workers/attempts. Zero local timeout does not reset the original global cap. |
| Shared failure limit | A real failure occurs while another file is in its actual body. Native stop aborts that peer and prevents later repeats; raw failed/interrupted outcomes remain distinct. |

Repeats within one file are serial in the first activation. The worker-cap and failure-limit controls therefore use two real files. The checker does not invent concurrent same-file execution. Small filesystem beacons expose actual body readiness; they neither select work nor supply native completion receipts.

Each process runs under the production native subreaper supervisor. Assertions occur after actual supervisor completion. The checker retains raw stdout/stderr, full genuine reports, actual supervisor waitpid facts and frozen product/SDK hashes. It verifies native collection/execution host waitpid timing (deduplicated by actual worker index and PID), exact attempt/output owners, the shared final physical-budget receipt and absence of all observed PIDs including zombies. Opaque logical IDs are compared against the native selected-slice mapping, never parsed as authority. Local attempt IDs and generations remain unchanged in source reports; repeated public IDs belong to the typed mapping.

Numeric overflow, huge counts, metadata capacity and invalid integer domains belong to the bounded C++ leaf controls, not expensive host loops. This driver does not claim CEF, attachment writer, arbitrary fixture or full upstream-suite parity. It must run only after Forms' activation build is ready and Root grants the actual lane.

Root registration: include `repeat_execution_proofs.cmake` from `native/runner/CMakeLists.txt` after runner proof variables are set. The public guard is 836 seconds: fourteen original 45-second case supervisors, each with one-second cleanup and ten-second physical grace, plus 52 seconds for orchestration. The checker creates a fresh owned directory and does not delete prior evidence. No retry-to-green or full-suite replay is part of this proof.

`check-native-runner-repeat-contexts.py` is a separate adversarial host component. It starts actual emitted Node Host children with an owned duplex fd3, reads genuine metadata through `LOADED`, then supplies explicitly authored missing/foreign repeat-map packets. These inputs are not native admission receipts. Python records each actual PID and kernel start, real `os.waitpid` status, control/stdout/stderr EOF and exact `HOST_ERROR`; expected-failure declarations must not turn this infrastructure error into a raw callback result. No author beacon or body/hook result is permitted. The three controls run under the production native supervisor, separately from the public native-runner cases. They make no public native scheduling or repetition parity claim.

Private emitted SDK execution needs declared ordinary runtime packaging: module package metadata with flat emitted self-export paths and a dependency link to existing installed packages. The controlled host checker resolves `zod`, `suitecut`, and `suitecut/native` before starting a host, and pins the actual resolved Zod package contents as well as emitted SDK bytes. No package installation, dependency implementation copying, or normal product change is part of this setup. The first missing-package startup negative is retained separately from the corrected component proof.
