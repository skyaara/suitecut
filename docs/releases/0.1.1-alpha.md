# suitecut 0.1.1 alpha: release record

A fix release for macOS arm64. This page records what was built, from which
sources, and what was checked, as `RELEASING.md` asks. The archives were built
and checked on 2026-11-23 on macOS 27.0.1 (Apple M4, 16 GB). They are not
published or notarized yet; notarizing staples tickets into the apps, so the
archives and hashes below will be rebuilt then.

The runtime is no longer held. Its engine is the official CEF build and its
FFmpeg is an LGPL-3.0-or-later build whose complete source ships inside the
archive (`share/src/ffmpeg-9.0.2.tar.xz`), with the FFmpeg, libvpx and opus
licences in `share/doc/SuiteCutRuntime/media/`. Its manifest records
`redistributionReady: true` and no `publicationHold`.

All binaries are signed with the Developer ID certificate of team `WTD7AF5L23`,
timestamped, with the hardened runtime. None is notarized yet.

No archive names the build machine's folders: the last gate searches every
packaged file for the home and repository paths.

Limits of these checks:

- macOS ASan has no leak detector, so no leak check ran. Prebuilt CEF is not
  sanitizer instrumented.
- Nothing was run on macOS 14 or 15 themselves. The minimums are what every
  packaged Mach-O file declares, enforced by the packager's `--require-macos`.
- Linux x64 was not built or tested. Windows packaging does not exist.

## Known issues

- Not notarized yet: a downloaded copy of the embed kit's or runtime's app is
  blocked by Gatekeeper until it is.
- Software VP9 (`.webm`) kept 110 distinct FPS at 3840×2160 when asked for 120;
  `.mp4` kept 120.
- The runtime's engine is the official CEF build, so pages cannot play H.264,
  AAC or HEVC. Recording to `.mp4` still encodes H.264 through VideoToolbox.
- Codec playback acceptance and folder upload have no native checks yet.
- The 0.1.0 archives name the folders of the machine that built them.
