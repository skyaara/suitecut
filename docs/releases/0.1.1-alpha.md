# suitecut 0.1.1 alpha: release record

A fix release for macOS arm64. This page records what was built, from which
sources, and what was checked, as `RELEASING.md` asks. The archives were built
and checked on 2026-11-24 on macOS 27.0.1 (Apple M4, 16 GB). The four
archives and their `SHA256SUMS` were published on 2026-11-24, not notarized,
as the GitHub pre-release
[`native-v0.1.1`](https://github.com/skyaara/suitecut/releases/tag/native-v0.1.1).
Notarizing staples tickets into the apps, so a notarized build will have new
archives and hashes.

The runtime is no longer held. Its engine is the official CEF build and its
FFmpeg is an LGPL-3.0-or-later build whose complete source ships inside the
archive (`share/src/ffmpeg-9.0.2.tar.xz`), with the FFmpeg, libvpx and opus
licences in `share/doc/SuiteCutRuntime/media/`. Its manifest records
`redistributionReady: true` and no `publicationHold`.

All binaries are signed with the Developer ID certificate of team `WTD7AF5L23`,
timestamped, with the hardened runtime. None is notarized yet.

No archive names the build machine's folders: the last gate searches every
packaged file for the home and repository paths.

## Checks

Gates are numbered as in `RELEASING.md`.

| 2. Client tests | Release: 26 of 26 (static and shared). ASan and UBSan: 26 of 26, linked against the static OpenSSL. |
| 2. Fuzz campaigns | JSON and packets, seed `5355495445435554`: 5,000,000 iterations in Release, 1,000,000 under ASan. Agent observation, seed `4147454e545549`: 500,000 in Release, 50,000 under ASan. |
| 3. Control CLI fuzz | `fuzz-native-control.py`, seed `53455353494f4e`: 10,000 iterations; worker descriptors (12) and threads (2) flat, memory grew 0.1 MB. |
| 4. Engine checks | 192 pass, with `native-http-lookup-transport` skipped. |
| 5. CEF regression suite | 5 of 5 C++ workflows, seed 23; 41 of 41 harness unit tests. |
| 6. Installed SDKs | C and C++ consumers build and pass against relocated static and shared prefixes with Homebrew hidden from CMake. Both installed CLIs open a page and read its title with only `/usr/bin:/bin` on `PATH`. |
| 7. Runtime archive | Verified from a relocated extraction: 303 manifest hashes, signatures, the CLI without Node or Homebrew on `PATH`, and the live C++ browser checks. |
| 7. Recording | `.mp4`: 12 of 12, to 3840×2160 at 120 FPS. `.webm`: 12 of 12. Audio cases open with at most 10 ms (`.mp4`) and 30 ms (`.webm`) of quiet. |
| 8. Embed kit | `verify-embed-kit-macos.py`: 56 of 56. `verify-embed-sample-macos.py`: pass. |
| Extraction | Every app and executable in all four archives passes `codesign --verify --deep --strict` after extraction; none contains the home path. |

Limits of these checks:

- macOS ASan has no leak detector, so no leak check ran. Prebuilt CEF is not
  sanitizer instrumented.
- Nothing was run on macOS 14 or 15 themselves. The minimums are what every
  packaged Mach-O file declares, enforced by the packager's `--require-macos`.
- Linux x64 was not built or tested. Windows packaging does not exist.

## Known issues

- Not notarized yet: a downloaded copy of the embed kit's or runtime's app is
  blocked by Gatekeeper until it is.
- Software VP9 (`.webm`) kept 71 distinct FPS at 3840×2160 when asked for 120
  (between 44 and 110 across runs on this machine, depending on load); `.mp4`
  kept 120.
- The runtime's engine is the official CEF build, so pages cannot play H.264,
  AAC or HEVC. Recording to `.mp4` still encodes H.264 through VideoToolbox.
- Codec playback acceptance and folder upload have no native checks yet.
- The 0.1.0 archives name the folders of the machine that built them.
