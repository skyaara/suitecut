# Native continuous publishing

`createNativeBroadcast` uses the browser binary for CEF video/audio ingestion, frame-rate conversion, FFmpeg execution, pipe backpressure, and publisher lifetime. The SDK sends controls and receives native counters. It does not subscribe to host frame/audio callbacks or spawn a publisher.

The compatibility wrapper publishes H.264/AAC in FLV over RTMP/RTMPS. `createNativePublisher` also exposes VP9/Opus in WebM over TCP, explicit codec/container choices, startup deadlines, and bounded write lag. Capture remains an integer rate from 1 through 120; the output rate accepts finite values from 1 through 120, including 29.97. Held output slots are measured separately from actual incoming frames.

Creation waits for observed encoded output. `ready()` consequently resolves after creation. `status()` and `health()` return promises for actual `NativeStreamingInfo`; previous synchronous capture/output lag fields are no longer exposed. Encoded and muxed counters indicate observed local FFmpeg progress, not receipt by a remote service. AAC decoding can include codec priming and padding.

`selectSource(source)` returns the native acknowledgement and accepts actual pages in the same browser helper. `pause()` holds the image and emits silence while the live timeline continues; `resume()` restores ingestion. `stop()` waits for physical encoder completion. `cancel()` reports native cancellation. Graceful page/context/browser closure finalizes the publisher; crashes and forced termination report failure.

Omitted or false `reconnect` makes one publisher attempt. An explicit policy enables C++ reconnect: `maxAttempts` permits 1 through 8 replacements per outage, `initialDelayMs` accepts 0 through 5000, and `maxDelayMs` accepts values from the initial delay through 30000. Defaults are 3 replacements, 250 ms initially, and 5000 ms maximum. The direct `createNativePublisher` API also accepts `timeoutMs` inside the policy, from 1 through 120000 ms, defaulting to 30000 ms. The compatibility wrapper uses that 30000 ms outage budget. Unsupported or unlimited values reject before native admission; they are not silently capped.

The first encoded-readiness command retains its original deadline across replacements. A later outage budget starts at the actual observed network or child failure, including physical child cleanup. Backoff, wakeups and retries run in C++. A successfully encoded replacement resets the outage budget. Cancellation, page crash, owner closure, quota failures, malformed configuration and bounded pipe-lag failures remain terminal. Before first readiness, a child failure is retryable only when its actual diagnostics identify a network failure. An encoder is physically reaped before its replacement is launched. Linux process identity descriptors prevent signaling a recycled PID; a kernel supporting `pidfd_open` and `pidfd_send_signal` is required.

`status()` reports `reconnecting` between attempts, with physical encoder PID zero only after the old child exits. Existing output counters, duration and media origin describe the current attempt; `cumulative*` counters sum actual local attempt progress. `firstCapturedTimestampMs` preserves the genuine retained image capture time separately from the replacement output origin. The last eight attempt records retain actual PIDs, timestamps, local counters, child settlement and bounded diagnostics, with explicit truncation. These values do not imply continuous remote delivery or acknowledgment. Incoming pictures during an outage retain only the latest real image, and captured PCM queued or arriving while disconnected is dropped with explicit disconnected counters. Those counters describe captured input discarded offline, not all bytes lost in a failed remote publication. The existing four-publisher, picture-byte and PCM bounds apply throughout reconnection.

`adaptiveBitrate: true` and `onDiagnostic` remain explicitly unsupported. Use `status()` or `health()` for native counters and `failure` for actual terminal errors. Runtime bitrate changes and cross-helper source switching are not supported.

The audio-enabled publisher buffers 120 ms of captured media by default; `captureLatencyMs` accepts integer values from 20 through 1000. Video slot `n` selects a genuine picture captured at or before that slot's timestamp, and waits for its complete interval before submission. PCM advances independently in 20 ms chunks on the same 48 kHz timeline. Encoded timestamps retain the captured origin. `captureLatencyMs` and `videoIntervalClosureMs` describe this policy; `maxCaptureToPipeMs` measures actual local pipe submission delay and does not measure remote latency.

Pause/resume and selection take effect at their actual native command timestamps. Already buffered earlier media retains its original meaning. Audio not available by its playout time becomes counted silence; late overlap, deliberate pause, selection discards and stop trimming have separate counters. A final partial CFR interval is trimmed when stopping; `stoppedAudioFrames` and `stoppedVideoFrames` disclose remaining captured input. Exact sample counts do not by themselves establish continuity or synchronization. The authored CEF timing verifier decodes continuous tones and common-clock audio/visual pulses at 120, 59.94 and 29.97 FPS.

Picture payloads, including held and in-flight references, are bounded to 256 MiB per publisher and 1 GiB across the Engine, alongside the existing four-publisher limit and 30-second PCM queue. Actual allocation is released before its byte reservation is reusable. Quota and pipe-lag overflow fail explicitly. CEF surfaces, process allocations and FFmpeg memory are additional. Child renderer failures are isolated; generic helper/protocol failures remain fatal. See [native renderer recovery](native-renderer-recovery.md) for the separate reload and epoch contract.

Child-page renderer failure is isolated from healthy pages in the same native helper. A failed child rejects its pending DOM commands and source failure promise; native recording and publishing retain their encoder ownership until actual process exit and socket EOF. Page/context closure still waits for the real CEF close callback. Status/stop/cancel remain available for native media ownership after renderer failure. A generic helper/protocol error and failure of the initial root page retain their existing fatal behavior. Child reload recovery follows the [native renderer recovery](native-renderer-recovery.md) contract.

Public child-page crash events (`on`, `once`, `prependListener`, `off`, and `waitForEvent('crash')`) are emitted from the actual CEF renderer termination callback. Native journal cursors and original wait deadlines survive that renderer failure, including an asynchronous host predicate. A false predicate continues waiting under its original deadline; registering after the crash does not replay the event. A crashed child remains physically open until its page/context closes. Existing DOM operations fail, while healthy pages and native media settlement remain independent. Child reload recovery is separately admitted by genuine native document and Runtime readiness, as described in [native renderer recovery](native-renderer-recovery.md).

Crash-listener exceptions are rethrown asynchronously after page failure cleanup. Error instances retain their identity; other thrown values are preserved as the cause of an Error. Other crash listeners still run. The library installs no process exception handler, so the application retains normal control of unhandled exceptions.
