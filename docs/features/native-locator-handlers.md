# Native locator handlers

`page.addLocatorHandler(locator, handler, { times?, noWaitAfter? })` registers a lazy locator or retained native `NativeElementHandle` on that actual page. The callback receives the same object. Normalized locators use their existing built-in query description; fixed handles resolve the exact retained node and never reselect after disposal or document loss. The native browser decides when an eligible action observes the overlay, serializes invocation, consumes `times` and waits for hiding unless `noWaitAfter` is true. Handler work shares the triggering action’s original native deadline.

`page.removeLocatorHandler(locator)` identifies the exact registered locator object in this first slice. An unknown locator is a no-op. Duplicate registration of that same object is rejected until native removal/retirement. Removal from inside its own callback disables the native registration but rejects the self-wait; it cannot claim that the still-running callback has retired. Native `times` exhaustion can also remove the registration. Snapshot-reference registrations retain immutable native token and document identity. Each observation uses the native query controller’s transient borrow; replacing a snapshot or navigating makes the registration stale instead of rebinding it.

Native handlers belong to a page, including its actual child-frame targets. Separate pages in the same native browser process can be used by a callback; a different browser process cannot borrow its native operation capabilities. The SDK preserves the actual triggering command’s async context rather than the registration caller’s context.

The SDK executes the real callback and reports its actual settlement. A callback’s unawaited, genuinely admitted built-in operations retain native-issued operation tokens; new work inherited from a closed callback context is rejected. Those tokens are not physical retirement evidence: native Inspector/input/task ownership and the actual native retirement event remain necessary. Page closure closes new handler admission but does not settle an arbitrary callback promise. Native Source child death likewise does not settle a callback still executing in Node. Page closure itself does not wait for that callback’s raw return.

Native overlay-enabled action families include `selectText`; `press`, `type`, `sendKeys`, raw focus and evaluation do not trigger handlers. Callback command coverage is bounded by the native allowlist. Audited HTTP/body/upload/cookie/storage, routing, artifact/video/download, trace/HAR, debugger/coverage, context/page lifecycle and worker operations now retain their actual native asynchronous work. A live page's callback can reload a different failed child page: recovery retains each joining invocation through actual new renderer, committed document, Runtime and utility-context observations. Unknown actions, test-framework screenshot comparisons and opt-in direct CEF input remain excluded. A successful recording or stream start transfers its producer to the resident registry only at the real Started receipt; canceled starts and stop operations remain retained through the actual encoder join. There is no JavaScript visibility polling, handler scheduler, timeout, retry loop or `times` counter. With no registered handler, no extra native requests or action-context snapshots are added.

Renderer recovery uses the existing `NativePage.reload()` path, which selects the native `recoverPage` command for a failed page. The originating live callback keeps its own original action deadline. Canceling or timing out its reload observer does not retire the accepted CEF reload. Recovery failure or a nonrenewing 30-second physical cleanup grace after an invocation loses its last observer requests actual child-page closure; only `OnBeforeClose` discharges an unresolved recovery receipt. Multiple invocations joining one reload each retain a receipt. A crash of the callback's own page still cancels its original action/invocation epoch, so this support does not revive that callback or its stale handles.

Native I/O receipts preserve invocation origin across actual callbacks and captured
state destruction. Logical cancellation cannot discharge the outstanding work.
The process-wide invocation allocator prevents later Engine instances from
borrowing an older callback's identity. Ordinary commands outside handlers do not
allocate these receipts. Context/page shutdown and initial page creation retain
their actual lifecycle boundaries. These are implementation/compile properties;
broad E2E and fuzz verification are deferred.
