# Native output preservation — following design

This private following unit concerns successfully assigned native attempt output
trees only. The existing creation/assignment history, empty preparation rollback,
original deadlines and real helper exits remain unchanged. It is not activated
from the current frozen build. The policy/report/fence17 and genuine filesystem-helper8 controls pass optimized
and ASan/UBSan/LSan against captured current integration headers. The finalizer adds seven optimized/sanitizer controlled groups;
central wiring and Node-runner checker remain uncompiled/unexecuted; no public
runtime retention capability is claimed yet.

## Existing behavior and scope

`RunnerOutputDirectories` already creates unique inode-pinned attempt roots,
waits for actual creation-helper exit and genuine host assignment ACK, and shares
physical IO capacity with attachments. `outputPath` only joins bounded relative
segments and creates no files. Completed roots and arbitrary author children are
currently retained. Native committed attachments live in separate
`suitecut-attachments-*` roots under the report parent; this unit must not delete
or relabel those artifacts. Snapshot/attachment naming templates and separate
attachment/screenshot/video/trace retention remain later contracts.

The pinned public1.64 type `test.d.ts:1587` documents `preserveOutput` default
`always`, plus `never` and `failures-only`. No external implementation was read. One granted public-only no-browser oracle
recorded five actual paths for four tests: expected failure removed its output;
unexpected pass retained it; retry0 failure retained its distinct output despite
a passing retry1 whose output was removed; fixture teardown failure retained its
output. The supervised actual process exited1 for the deliberately unexpected
outcomes, with empty stderr, unchanged pinned inputs and real physical closure.
Evidence is `/tmp/suitecut-preserve-output-stock-v1`. This is a stock reference
observation, not a native runtime proof.

## Authoritative retention and lifetime

C++ receives exact native finalized attempt facts, retry and expected status,
and the matching assigned `OutputDirectoryRecord` owner/generation/worker/PID.
Each retry retains its own decision; a later passing retry cannot overwrite an
earlier outcome. `always` preserves by policy without IO and makes no current
availability assertion. `never` requests cleanup. The `failures-only` policy uses the finalized native expected/unexpected
classification, matching those public reference cases. A genuine native runner
proof still must establish that actual teardown failures reach that finalized
classification before a deletion decision.

Cleanup starts only after all actual hosts, user descendants, raw callbacks,
steps, files, publication-view ACKs, output preparation and retained Source work
are physically retired. A reused live host cannot authorize cleanup. Central
native final-publication hooks must supply those real fences; neither status nor
logical operation count stands in for them. A dedicated native cleanup helper
holds shared physical IO capacity through its actual protocol receipt AND
waitpid-confirmed exit, including cancellation and delayed ACK. A fixed cleanup
budget requests a real helper kill when expired; expiry never manufactures
physical retirement. Reports cannot publish while a cleanup helper remains live.

The helper opens the exact parent/root without following symlinks and verifies
recorded parent/root device+inode. A bounded nondestructive inventory pins every
child identity before removal. It never follows symlinks or crosses mount IDs.
Execution rechecks each actual entry identity; replacement is preserved and is a
real failure/foreign observation. Tree depth, entry count, name storage and the
original cleanup deadline bound planning/removal. A failure may have removed
only part of the tree, which is reported as unknown partial availability.
Cleanup fsyncs actual affected directories and the parent before final success.

Creation, assignment and committed artifact records remain immutable. Separate
native retention rows distinguish kept/unobserved, removed original location,
already absent original location, a preserved foreign replacement and failed or
partial cleanup. No row claims global inode destruction or file availability
from a path string. Original attempt errors stay primary; a genuine cleanup
failure additionally fails the run and remains visible with its actual OS error.

## Report activation and remaining integration

An optional native run policy activates the retention section only when explicitly configured.
Omitting the option preserves existing default-always behavior and report shape. Activated reports
require exactly one matching row for every READY, assigned output record, the
same policy on each row, and exact final native attempt facts. Legacy reports
without this feature keep their existing shape. Failure before helper admission
requires an actual native decision receipt; a helper row requires actual waitpid
and channel EOF retirement. Cleanup budgets are finite and capped at30 seconds
for the whole final cleanup phase; queued work does not renew that budget.

A private, component-tested finalizer pre-admits all applicable rows before any
destructive work, uses one original30-second phase clock, waits for actual helper
retirement, and only then publishes the activated policy and sidecar. The
following central work remains unimplemented: native/CLI/SDK option routing,
calling that finalizer after the existing physical fences, helper mode
dispatch, report JSON/JUnit/HTML sidecar wiring, and registered controls. No
Renderer, Source or live-host reuse path will infer cleanup readiness.

The filesystem contract does not serialize external writers. Identity checks
reject observed replacements, but the kernel has no inode-conditional unlink
transaction for an arbitrary racing external writer between the final stat and
unlink. No stronger external-race guarantee is claimed.
